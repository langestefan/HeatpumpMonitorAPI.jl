# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`HeatpumpMonitorAPI.jl` is a Julia client for the
[HeatpumpMonitor.org](https://heatpumpmonitor.org) public REST API
(community-submitted heat-pump performance data: COP, flow/return temps,
energy use, weather compensation, per-feed timeseries). The package was
scaffolded with [`OpenAPITemplate.jl`](https://github.com/langestefan/OpenAPITemplate.jl)
on top of an OpenAPI 3.1 spec we **reverse-engineered** from the
upstream API helper page — there is no official spec.

## Layout — what is generated vs hand-written

```text
src/
  HeatpumpMonitorAPI.jl  # main module (template-rewritten + ONE manual line — see below)
  api/                   # generated by openapi-generator-cli — DO NOT EDIT
    HeatpumpMonitorAPIAPI.jl
    apis/                #   api_SystemApi.jl, api_TimeseriesApi.jl
    models/              #   model_SystemMeta.jl, model_SystemStats.jl, ...
    modelincludes.jl
  client/                # hand-written template overlay (Client, Auth, retry, etc.)
  conveniences/          # OUR HeatpumpMonitor-specific helpers (do not regenerate)
    conveniences.jl      #   HeatpumpMonitorClient, heatpumpmonitor_apis
    helpers.jl           #   as_number, parse_daily_stats, flatten_timeseries
gen/
  regenerate.jl          # rerun codegen against spec/openapi.json
  emit_api_pages.jl      # refreshes docs/src/api/<Tag>.md from spec
  openapi-config.json
spec/
  openapi.json           # canonical OpenAPI 3.1 spec consumed by codegen
scripts/
  smoke_test.jl          # exercises every operation against the live API
test/
  test-*.jl              # auto-walked by runtests.jl
  cassettes/             # BrokenRecord HTTP fixtures (committed)
```

The generated `src/api/` directory is committed plain Julia. End users
never need Java or Node. Re-running `gen/regenerate.jl` nukes and
re-creates `src/api/` only.

### The one manual edit to a templated file

`src/HeatpumpMonitorAPI.jl` is a templated file but `gen/regenerate.jl`
does not touch it. We added two lines near the end:

```julia
include("conveniences/conveniences.jl")
export HeatpumpMonitorClient, heatpumpmonitor_apis, DEFAULT_BASE_URL

```

If the *full* PkgTemplates scaffold is ever re-run (rare), re-add these.

## How `spec/openapi.json` was built

HeatpumpMonitor.org publishes only a human-readable
[API helper page](https://heatpumpmonitor.org/api-helper) — no machine
spec, no Postman collection. The committed spec was produced by:

1. Reading the helper page's endpoint list and Python example.
2. Probing every endpoint live (`scripts/smoke_test.jl` and ad-hoc
   `python3 -c 'import requests; ...'` recon scripts) to learn the
   actual response shapes, field types, and quirks. Notes from that
   recon live in the spec's `info.description` and field descriptions.
3. Codifying those observations as OpenAPI 3.1 with permissive types
   that survive the upstream API's serialization quirks (see "API
   conventions" below). Validation: every documented property must
   appear in real responses, and real responses must validate against
   the spec via JSON Schema 2020-12.

`gen/regenerate.jl --no-fetch` reads the local `spec/openapi.json`
directly. The script's `SPEC_URL` is the local file path because there
is no upstream URL to pin to.

When the upstream API changes (new fields, new endpoints, new
`unit_rate_*` keys), update `spec/openapi.json` by hand and re-run
`gen/regenerate.jl --no-fetch`. Then run `scripts/smoke_test.jl` to
confirm OpenAPI.jl's deserializer still accepts the live responses.

## Key API conventions worth remembering

These quirks live in the live upstream service and the spec encodes
them explicitly. Helpers in `src/conveniences/helpers.jl` paper over
them for callers but you'll still see the raw shapes in the generated
return types.

- **Stats endpoints always return a map keyed by system ID.** Even when
  you pass `id=...`, the response is `Dict{String, SystemStats}` with
  one entry. Pull it out with `body[string(id)]`.
- **`/system/stats/monthly` stringifies every numeric field** while
  `/system/stats/last7|30|90|365|all` and `/system/stats` return raw
  JSON numbers. `SystemStats` numeric fields are typed
  `["number", "string", "null"]` in the spec to accept both. Use
  `as_number(...)` to coerce uniformly.
- **`timestamp` can be `false`** for systems that have never been
  scored (PHP-style empty). `as_number(false)` returns `nothing`.
- **`/system/stats/daily` returns `text/plain` CSV**, not JSON. Use
  `parse_daily_stats(csv)` to get one dict per day.
- **Timeseries timestamps are milliseconds, not seconds.** Each row is
  `[unix_epoch_milliseconds, value_or_nothing]`. Use
  `flatten_timeseries(...)` to convert to `(DateTime, Union{Float64, Nothing})`.
- **`end` query param is reserved in Julia.** The codegen renamed it
  to `__end__`; pass via ``var"__end__" = "..."`` at the call site.
- **`timeseries_data` with an unknown feed name** causes upstream PHP to
  inline a warning into the response body (HTTP 200 but invalid JSON).
  Always call `timeseries_available` first to discover valid feeds.
- **Boolean-style toggles in `SystemMeta` are integer 0/1**, not real
  booleans (`UFH`, `mid_metering`, `metering_inc_*`, `published`,
  `volumiser`, `hp_hybrid`, etc.). Several "numeric" fields round-trip
  as strings (`kwh_m2`, `battery_storage_capacity`, `dhw_target_temperature`,
  most `weighted_*`, etc.). The spec has these typed accurately.
- **`/system/list/user.json` is the only authenticated endpoint.** Auth
  is a session cookie (`PHPSESSID`) obtained via web login at
  `/user/login`. Pass it via `HeatpumpMonitorClient(; session_cookie=...)`.
  All other endpoints are public.
- **Dynamic `unit_rate_*` fields.** The stats response carries one
  `unit_rate_<tariff>` field per active tariff (Octopus Agile, Cosy,
  Go, Eon Next, etc.). New tariffs add new keys at any time — `SystemStats`
  has `additionalProperties: true` so they don't break deserialization.

## How a typical query reads

```julia
using HeatpumpMonitorAPI

client = HeatpumpMonitorClient()
apis   = heatpumpmonitor_apis(client)

# All public systems with their metadata
systems, _ = list_public_systems(apis.system)

# 90-day stats for one system — note the dict-keyed-by-id shape
stats, _ = stats_last90(apis.system; id = systems[1].id)
s        = stats[string(systems[1].id)]
as_number(s.combined_cop)         # works whether s.combined_cop is Number or "2.4"

# Timeseries
avail, _ = timeseries_available(apis.timeseries, systems[1].id)
keys(avail.feeds)                 # ["heatpump_elec", "heatpump_heat", ...]

raw, _ = timeseries_data(apis.timeseries, systems[1].id,
                         "heatpump_elec,heatpump_heat";
                         start = "1748000000",
                         var"__end__" = "1748086400",
                         interval = 3600, average = 1)
ts = flatten_timeseries(raw)      # (DateTime, value-or-nothing) pairs per feed
```

## When in doubt

- **Spec drift**: run `julia --project scripts/smoke_test.jl`. If any
  operation fails to deserialize, the spec is out of date with the
  live API. Inspect the failure, edit `spec/openapi.json` to match
  reality, re-run `gen/regenerate.jl --no-fetch`, repeat.
- **Cassette mismatch**: BrokenRecord matches request shape (URL +
  ignored headers). If you change a query parameter in a test (e.g.
  the timeseries window), the cassette must be re-recorded.
- **Re-running codegen overwrote something**: only `src/api/` is at
  risk. `src/HeatpumpMonitorAPI.jl`, `src/client/`, `src/conveniences/`,
  `test/`, `docs/`, and `spec/` are never touched.
- **JET/Aqua failing on Julia pre-release**: JET tracks Julia minor
  versions tightly and a brand-new pre often has no compatible release
  yet. The CI workflow has `continue-on-error` for `matrix.version == 'pre'`
  so this doesn't gate merges.
